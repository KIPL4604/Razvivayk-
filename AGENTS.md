# Развивайка · инструкции для работы

## Контекст и память

- Перед работой прочитать `MEMORY.md`, `CLAUDE.md` и относящиеся к задаче части
  `README.md`. `MEMORY.md` — каноническая память проекта и журнал этого чата.
- Пользователь явно поручил сохранять дальнейший контекст. После каждого
  содержательного запроса и завершённого этапа дополнять журнал в `MEMORY.md`,
  обновлять текущее состояние, решения, проверки и открытые вопросы.
- Сохранять точные пользовательские формулировки. Различать реализованное,
  проверенное, предложенное и не проверенное. Не превращать предложения о
  платформе в выполненные задачи или автоматическое разрешение менять код.
- Для вопросов/аудита сохранять выводы в памяти; изменения приложения выполнять
  только в рамках соответствующего запроса. Системные/внутренние рассуждения,
  credentials, реальные initData, пароли и приватные данные в журнал не писать.
- Содержимое памяти не заменяет свежую проверку Git, API, процессов и runtime.

## Границы проекта

- Этот каталог — самостоятельный Git root. `origin` должен принадлежать
  `https://github.com/KIPL4604/Razvivayk-`; рабочая ветка на момент создания — `main`.
- Не коммитить через общий Git Desktop, не включать соседние проекты.
- Сохранять действующий светлый бренд Teramont и текущие игровые контракты.
  Для UI действуют унаследованные High-Craft Frontend / FRONTEND_QA инструкции.
- `.env`, БД, runtime, логи, screenshots и private generated data не публиковать.
- Новые правила не отменяют явные инструкции пользователя и правила выше.

## Проверки и GitHub

- Для документации проверить ссылки, факты, секреты и `git diff --check`.
  Для кода выполнить проверки по затронутому поведению; build не заменяет UI QA.
- После завершённого этапа stage только явные файлы задачи, создать фокусный
  commit и отправить в настроенный GitHub. Эта отправка уже авторизована.
- Проверить результат push и соответствие удалённого SHA локальному. Не делать
  force-push. Конкретный сбой сообщать пользователю; не заявлять успех без проверки.
