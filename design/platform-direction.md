# Платформенная основа · 18 октября 2026

Запрос: реализовать переход из таблицы обсуждения к игровой платформе внутри
Telegram. Существующие 12 игр, кампании, светлый бренд и локальный гостевой режим
сохраняются. Полноценный онлайн сейчас подключается к покеру; шахматы остаются
игрой с компьютером. Новые игры подключаются через реестр возможностей.

## Наблюдаемый результат

1. Единый каталог возможностей и лобби: свои комнаты, приглашение по коду,
   поиск соперника, отмена поиска, восстановление стола.
2. Приватные снимки покера через WebSocket, авторизация первым сообщением,
   повторное подключение и восстановление актуального состояния. Ходы по REST
   остаются версионированными. Redis доставляет уведомления между процессами.
3. Облачные сохранения головоломок и шахмат с версиями и явным разрешением
   конфликта между устройствами. Гостевые сохранения остаются локальными.
4. Сервер выдаёт задания и проверяет решение перед XP; повторная отправка
   результата не начисляет опыт второй раз. Это проверка решения, а не защита
   от программного решения заданий или доказательство честности подсказок.
5. PostgreSQL для постоянного размещения, SQLite для простого локального запуска;
   контролируемый перенос данных, резервные копии, readiness, метрики, CI и
   конфигурация HTTPS-развёртывания. Само наличие конфигурации не означает,
   что публичный сервер уже запущен.

## Интерфейс

Главный путь: «Играть вместе» → поиск соперника / своя комната → стол → ход →
следующая раздача. Библиотека остаётся главным экраном. Лобби — отдельная простая
страница с одной заметной кнопкой поиска, списком реальных собственных комнат
и формой кода. Не показываем выдуманные счётчики онлайна и игроков.

Палитра #F5F7FB / #FFFFFF / #20263D / #667087 / #3567DC, системная кириллическая
типографика, размеренный ритм 8/16/24/32. Новые кнопки, поля и состояния используют
существующие токены. Белые строки с тонким разделителем вместо дополнительных
декоративных плиток. Анимация только обратной связи, reduced motion сохраняется.
Облачная запись обозначается короткой строкой состояния с работающей кнопкой
повтора; конфликт не разрешается без выбора пользователя.

## Порядок и границы работ

Сначала согласованные контракты БД, задания/доказательства решения и событий.
Независимые владельцы: адаптер БД и poker.py; game_store.py и генераторы; новые
platform/realtime/registry. Интеграция main.py, frontend, deployment и итоговая
проверка — у одного координатора (workflow code-work, adaptive parallelism).

## Приёмка

Проверить старые кампании и покер, поддельное/чужое решение, повторный XP,
конкурентное сохранение, две Telegram-сессии, поиск/отмена/приглашение, приватность
WS, переподключение, срок хода, рестарт API и восстановление из копии.
UI: два просмотра screenshots 375/768/1440/1920, клавиатура, потеря связи,
пустое лобби, конфликт записи, reduced motion. БД/Redis/HTTPS проверяются отдельно
в доступном окружении; ограничения инфраструктуры фиксируются по факту.
