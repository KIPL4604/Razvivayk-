# Локальные миры и восстановление связи в «Развивайке»

3 ноября 2026 года. Проект решения. Первый пилот — Биосад в Lumen.

## Как это работает для игрока

Первый вход открывает лёгкое меню. При запуске экспедиции скачиваются только ресурсы для управления героем и первых волн. Проверенные файлы остаются на устройстве и используются при следующем входе. Поздние волны и финал текущего мира догружаются заранее по ходу игры. Следующий мир можно скачать отдельно по кнопке с указанием размера. Автоматическая предзагрузка других миров выключена по умолчанию.

Если на переходе с Wi‑Fi на мобильную сеть оборвалась загрузка, уже проверенные части сохраняются. После возвращения связи очередь продолжает работу сама. Если игрок уже в забеге и все ресурсы текущей фазы на месте, он продолжает играть. Если обязательный файл понадобится раньше, чем успеет скачаться, игра сохраняет состояние перед переходом и предлагает дождаться связи, повторить запрос или вернуться в меню. При продолжении игрок возвращается к той же фазе.

## Где хранить игру

- **Cache Storage и обычный HTTP-кэш.** Основной путь для кода, графики и звука. Полные проверенные файлы лежат в Cache Storage. HTTPS-хостинг отдаёт файлы с хэшем в имени и долгим сроком кэширования, HTML и манифесты перепроверяются. Доступность хранилища, остаток места и поведение после полного закрытия Telegram проверяем на устройствах. Система может вытеснить данные, поэтому статус «Скачано» сверяется с фактическим наличием ресурсов. Запрос постоянного хранения допустим там, где WebView его поддерживает и выдаёт разрешение. [Стандарт веб-хранилища](https://storage.spec.whatwg.org/)
- **Telegram DeviceStorage.** Подходит для сохранений и настроек, которые уже используют этот механизм. Telegram указывает лимит 5 МБ на пользователя для бота. Для масштабирующегося каталога двоичные ресурсы храним в веб-кэше. Кэш медиа из переписки остаётся под управлением Telegram. Документированный Bot API для получения файла использует серверный токен в адресе, поэтому клиентскую доставку через него не строим. [Telegram DeviceStorage](https://core.telegram.org/bots/webapps#devicestorage), [Telegram Bot API getFile](https://core.telegram.org/bots/api#getfile)
- **Service Worker для запуска без сети после первого скачивания.** Отдельный эксперимент после пилота. В поддерживаемом WebView он может отдать сохранённые HTML, JS, CSS и ресурсы нужного мира. Нужно подтвердить, что Telegram вообще открывает Mini App без сети, а страница загружается без сетевой зависимости от Telegram SDK. До этого «Скачано» означает, что игровой контент доступен локально после открытия оболочки. Если полный офлайн-запуск внутри Telegram недоступен, можно отдельно оценить PWA в системном браузере. Ярлык Telegram на домашнем экране сам по себе офлайн-режима не добавляет. [Service Worker](https://w3c.github.io/ServiceWorker/), [ярлыки Telegram](https://core.telegram.org/bots/webapps#homescreen-shortcuts)

В пилоте предлагаем хранить основу игры, текущий мир и миры, которые игрок скачал сам. Лимит **30 МБ для пилота** — параметр продукта, который уточняется по тестам на телефонах. При нехватке места сначала удаляются старые необязательные ресурсы. Удаление скачанного мира освобождает только его файлы, а сохранения остаются. Активный забег держит свою версию графики до выхода. Если обновление выпущено, старые хэшированные файлы доступны в течение согласованного периода, чтобы открытая сессия могла завершить загрузку.

## Как передавать и возобновлять загрузку

1. **Разделить графику по моменту использования.** Манифест перечисляет размер, хэш и зависимости наборов. Для Lumen это общая основа, выбранный герой, старт мира, поздние волны, финал и необязательные материалы. Большие атласы доставляются несколькими проверяемыми частями, которые при сборке дают исходное изображение. Число запросов и размер частей подбираем по замерам. Текущий предел пакета 220 КБ даёт стартовую точку. Важнее изменить состав и порядок пакетов.
2. **Переиспользовать готовые части.** Один запрос на один хэш, приоритет у активного забега, сначала 1–2 параллельных скачивания. Записывать целую часть после проверки и считать её готовой после успешной записи или помечать временной, если доступна только память страницы. При обрыве повторно скачивается только незавершённая часть. После закрытия приложения очередь восстанавливается по манифесту и доступным проверенным файлам. Процент готовности считается по проверенным байтам. Отдельно можно показать, что текущая часть ещё передаётся.
3. **Ограничить повторы и дать очереди проснуться.** При сетевой ошибке или временном 5xx повторить с увеличением задержки и случайным разбросом. Для 429 учитывать `Retry-After`. События `online`, возврат в Telegram и кнопка «Повторить» запускают проверку связи раньше, с объединением повторных сигналов. Таймаут определяется временем без новых байтов. Для 404 один раз перепроверить манифест, для битого файла удалить только повреждённую часть и запросить её заново. У постоянной ошибки должен быть понятный выход из экрана загрузки.
4. **Догрузка внутри одного файла нужна только при доказанном выигрыше.** Если после деления останутся крупные файлы с частыми обрывами, сохранять частичные байты в IndexedDB и пробовать HTTP `Range` с `If-Range` и сильным ETag. Проверять код `206`, `Content-Range`, полный размер и итоговый SHA-256. Если сервер вернул `200` или версия файла сменилась, начать этот файл с нуля. Для коротких частей проще повторить одну часть целиком. [RFC 9110, Range Requests](https://www.rfc-editor.org/rfc/rfc9110.html#name-range-requests)

## Пилот и приёмка

1. **Получить базовую линию.** Один релиз на текущем маршруте и на постоянном HTTPS. Замерить время до каталога, меню Lumen и управления героем. Отдельно записать переданные байты, долю попаданий в кэш, ошибки и время восстановления. Первым миром взять Биосад, отдельно проверить продолжение сохранения на поздней фазе.
2. **Доставить стартовый набор и очередь повтора.** Цель из предыдущего разбора — до 500 КБ на старт Биосада и до 10 секунд до управления на профиле 1 Мбит/с и RTT 150 мс при быстром пропуске вступления. После повторного открытия с сохранённым кэшем ожидаем нулевую повторную передачу проверенных игровых пакетов этой версии.
3. **Проверить физические Android и iOS.** Чистый запуск, повторный вход, полное закрытие Telegram, очистка кэша и нехватка места. Переключение Wi‑Fi на мобильную сеть посреди части, обрыв на 2 и 30 секунд, ответ 502 и повреждённая часть. Проверить выход и возвращение на этапе загрузки, продолжение поздней фазы, сохранение прогресса и поведение после выпуска новой версии. Критерий после краткого обрыва — очередь продолжает работу сама, проверенные части не передаются повторно, прогресс забега сохраняется.
4. **Прогнать независимое восстановление сервисов.** На тестовом контуре отдельно прервать доступ к Telegram API, SSH и браузерное соединение. После восстановления проверить ответ бота на новую команду и открытие игры по прежней ссылке. В онлайн-покере сверить текущий снимок, срок хода и отсутствие дубля. Ручной перезапуск для краткого сетевого обрыва считается провалом проверки.
5. **Решить вопрос офлайн-входа.** После пилота проверить Service Worker и запуск скачанного мира без сети. Заявлять офлайн-запуск только для проверенной комбинации клиента Telegram и устройства. Для покера с другом, чата и подтверждения серверного прогресса нужна связь.

Первый релиз этого плана ограничен стабильной доставкой публичной статики, стартовым набором Биосада и восстановлением очереди. Работа с ботом и туннелем идёт по собственным диагностическим сценариям. Результаты реализации приведены ниже.

## Что заметит игрок и сколько это может дать

Согласованный порядок начинается со сравнения доставки одного релиза на постоянном HTTPS и через текущий туннель. Затем меняем состав стартового набора и очереди, отдельно облегчаем каталог. Для Lumen важны два горизонта. К первому кадру и первым пяти секундам готовы управление, герой, стартовое оружие, поле и первые противники. После начала игры приоритет у ресурсов, которые могут понадобиться в следующие пять минут. Пять минут — окно планирования, а не обязательный объём скачивания перед стартом. При продолжении забега приоритет определяет сохранённая фаза.

| Решение | Что заметит игрок | Риск и как его проверить |
| --- | --- | --- |
| Статика вне домашнего туннеля | Меньше долгих зависаний и повторов при открытии | Проверить один релиз по двум адресам. До переключения публичной ссылки проверить маршруты с целевых мобильных сетей, старые кнопки бота и сохранения при смене origin. |
| Разделение ресурсов по моменту использования | После входа файлы догружаются за игрой | Слишком мелкие файлы добавят задержки, слишком поздняя загрузка вызовет паузу перед встречей с врагом. Группировать по игровым фазам и давать обязательным файлам запас времени. |
| Лёгкий каталог | Список игр доступен раньше, чужие режимы не занимают соединение | Часть задержки может переехать на клик по карточке. Проверять время и до каталога, и до игры по одному сценарию. |
| Скачивание начала мира и отдельных миров | Первый забег начинается раньше, повторный использует скачанное | При нехватке места кэш может исчезнуть. Статус готовности проверяется по файлам. Запас под текущий мир важнее фонового скачивания следующего. |
| Возобновление по частям | Короткий обрыв не сбрасывает экран и готовые файлы | Повторы могут забить канал, а прогресс перескочить назад. Ограничивать очередь и показывать долю подтверждённых байтов. |
| Независимое восстановление бота, туннеля и Mini App | После возвращения сети игра или команда оживают без ручного перезапуска | Агрессивный перезапуск может создать конфликт двух poller. Проверять маршруты раздельно и сохранять одну активную сессию polling. |

### Игра уже знает следующий выбор оружия

В `engine.mjs` есть `nextUpgrade` для ближайшего повышения с максимум тремя вариантами. Выбор рассчитывается по состоянию забега, сохраняется, обновляется после изменения арсенала и не зависит от времени загрузки. Контроллер уже передаёт этот набор в фоновый загрузчик иконок. В текущем `preloadScene` при этом появилась общая обязательная загрузка иконок до вступления. Все 24 изображения вместе занимают около 19 КБ, но на нестабильной сети отдельные запросы и повторы могут задержать старт. [План выбора и проверка](lumen-upgrade-prefetch/review.md), [текущая подготовка сцены](../webapp/frontend/js/lumen/preload.mjs)

Первый шаг по Lumen — убрать зависимость старта от всех иконок и применить существующий план. Как только движок знает ближайший выбор, клиент запрашивает его иконки. Игрок повышает уровень и выбирает сразу, при задержке доступна та же карточка с текстом и нейтральным знаком. После выбора клиент готовит следующий набор. Боевые спрайты и эффекты отделяем от иконок: стартовый эффект готов к первому удару, остальное догружается с опережением или использует полноценный запасной визуальный эффект. Сетевые задержки не меняют состав вариантов, характеристики оружия и боевой RNG. Telegram-бот даёт ссылку, очередь ведёт клиент игры.

### Как считать эффект

- Для Биосада текущие пакеты спрайтов на 1,07 МБ требуют примерно 8,6 с чистой передачи при 1 Мбит/с. Бюджет всего старта в 500 КБ соответствует примерно 4 с передачи. Потенциальная разница по объёму — порядка 4,6 с на таком канале, если бюджет достигнут. Это расчёт без RTT, декодирования и повторов. Выигрыш от нового маршрута и реальные секунды до игры измеряются отдельно.
- Сравнивать холодный и повторный запуск. Отдельно мерить открытие каталога, меню, время от «Начать» до управления и суммарное время, когда игрок видит обязательное ожидание. Для каждой конфигурации фиксировать медиану и p95, а также долю запусков с ошибкой или ручным повтором. Время, потраченное на чтение вступления, учитывать отдельно.
- Для первых пяти минут считать долю забегов хотя бы с одной сетевой паузой, количество таких пауз и их общую длительность. Отдельно считать долю открытий выбора улучшения с нейтральной иконкой. Пилот проходит, если старт укладывается в оговорённый бюджет, а при контрольных прогонах первые пять минут и выбор улучшения не блокируются сетью. Реальное значение частоты пауз появится после замеров на телефонах.

## Результат первого пилота

Биосад для Следопыта получает два стартовых пакета общим размером 184 924 байта вместо шести пакетов на 1 069 710 байт. Два пакета с графикой боссов (374 264 байта) догружаются после запуска. Позднее сохранение запрашивает нужную графику сразу. Иконки ближайшего повышения готовятся по существующему плану, а вступление и выбор оружия работают при отказе этих запросов. Начальный набор включает боевые эффекты, необходимые для запуска. Cache Storage хранит целые проверенные пакеты, очередь повторяет временные ошибки и возобновляет запуск после возврата сети.

Каталог сохранил оформление и маршруты. Стили пяти игровых режимов и контроллеры шахмат и покера загружаются при открытии, с коротким текстовым статусом ожидания. Edge на ширинах 375, 768, 1440 и 1920 показал 28 запросов к своему серверу и 183 451 переданный байт вместо 38 запросов и 229 363 байт. Проверены клавиатурный вход, повтор после ошибки, отмена перехода при уходе на другой экран и рабочие игровые маршруты.

Измерение до управления в Edge, viewport 375 px, эмуляция 1 Мбит/с и RTT 150 мс. Старый и новый код запускались на отдельных loopback-адресах, вступление пропускалось сразу. Медианы трёх холодных прогонов приведены отдельно по этапам. Повторное открытие измерено один раз.

Это проверка контрольной точки. Непрерывный пятиминутный забег и частота пауз на физических устройствах остаются следующими замерами.

В изолированном Caddy каталог и графика обслуживаются при недоступном API. Версионированный пакет получает долгий кэш для 200 и 206, HTML и манифест перепроверяются, недостающий пакет не попадает в долгий кэш. Это сравнение одного файла, боевой адрес Mini App остаётся на текущем маршруте.

Бот повторяет стартовые обращения к Telegram при временной сетевой ошибке, затем запускает один polling. Mini App выявляет зависший WebSocket и восстанавливает подписку после возвращения сети. В отдельном Chromium с тестовой авторизацией одно отключение на 1 с прошло с восстановлением WebSocket и без ошибок JavaScript. Текущий SSH launcher уже восстанавливает туннель независимо. Для публичной приёмки нужны постоянный HTTPS-адрес, проверка Telegram на Android и iOS, а затем перенос схемы на остальные миры и отдельное скачивание мира по запросу.

В расширенном Node-прогоне обнаружены пять падений в `specimen-physics.mjs`, те же пять воспроизведены на исходном `8a384d9`. Длительные сценарии миров не входят в локальный прогон этого этапа.
